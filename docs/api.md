# TrackFresh API

HTTP-сервис на Node.js + TypeScript (Express), единственная точка доступа мобильного приложения к PostgreSQL.
Спецификация: `openspec/specs/data-api/`.

## Запуск

```bash
cd api
npm install
npm run build
npm start
```

Переменные окружения (все обязательны, кроме `PORT` и `PGPORT`):

| Переменная | Назначение | Пример |
|---|---|---|
| `PORT` | порт сервиса | `3000` |
| `PGHOST` | хост PostgreSQL | `192.168.3.69` |
| `PGPORT` | порт PostgreSQL | `5432` |
| `PGDATABASE` | база | `mydb` |
| `PGUSER` | роль | `trackfresh` |
| `PGPASSWORD` | пароль роли | — |
| `FIREBASE_PROJECT_ID` | проект Firebase | `trackfresh` |
| `FIREBASE_CLIENT_EMAIL` | сервисный аккаунт | `...iam.gserviceaccount.com` |
| `FIREBASE_PRIVATE_KEY` | приватный ключ (`\n` экранированы) | — |

Если переменная не задана, запуск завершается с сообщением вида
`Ошибка конфигурации: не задана переменная окружения PGHOST`.

## Аутентификация

Каждый запрос к `/products` и `/settings` обязан содержать заголовок:

```
Authorization: Bearer <Firebase ID token>
```

Токен проверяется на сервере; по идентификатору Firebase находится профиль (создаётся при первом обращении).
Без токена или с недействительным токеном — `401`.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка живости, без аутентификации |
| POST | `/products` | создать продукт |
| GET | `/products` | список продуктов профиля, отсортированный по сроку годности |
| PATCH | `/products/:id` | изменить поля продукта |
| DELETE | `/products/:id` | удалить продукт |
| GET | `/settings` | настройки уведомлений (при первом чтении — значения по умолчанию) |
| PUT | `/settings` | заменить настройки уведомлений |

### POST /products

```json
{
  "id": "3f1a9c1e-0a0b-4c2d-8e3f-111122223333",
  "name": "Молоко",
  "category": "food",
  "expiryDate": "2026-11-01",
  "productionDate": "2026-10-01"
}
```

`category` — `food` или `medicine`. `expiryDate` обязателен, `productionDate` — необязателен.
Даты только в формате `YYYY-MM-DD` и должны существовать: `2026-02-30` и `2026-99-99` отклоняются с `422`.

`id` необязателен: клиент может прислать свой идентификатор (uuid), чтобы повторная отправка после обрыва связи не создала второй продукт. Если `id` уже занят продуктом того же профиля, возвращается `200` с существующим продуктом; если идентификатор принадлежит другому профилю — `409`.

Ответ `201` (или `200` при повторе):

```json
{
  "id": "…uuid…",
  "name": "Молоко",
  "category": "food",
  "expiry_date": "2026-11-01",
  "production_date": "2026-10-01",
  "updated_at": "2026-10-28T20:31:07.412Z"
}
```

`updated_at` — момент последнего изменения в формате ISO 8601 с часовым поясом; присутствует в каждом продукте во всех ответах и растёт после `PATCH`.

### GET /products

Ответ `200` — массив продуктов, ближайшие к истечению первыми.

### PATCH /products/:id

Тело — только изменяемые поля (`name`, `category`, `expiryDate`, `productionDate`).
`productionDate: null` очищает дату производства. Ответ `200` — обновлённый продукт с новым `updated_at`.

### DELETE /products/:id

Ответ `204` без тела.

### GET /settings

```json
{ "notify_frequency": "daily", "notify_time": "09:00", "warn_days": 3 }
```

### PUT /settings

```json
{ "notifyFrequency": "weekly", "notifyTime": "07:30", "warnDays": 7 }
```

`notifyFrequency` — `daily`, `every_3_days` или `weekly`; `notifyTime` — `HH:MM`;
`warnDays` — целое от 0 до 365. Ответ `200` — сохранённые настройки.

## Ошибки

| Код | Когда |
|---|---|
| `400 bad_request` | тело запроса не разобрано (некорректный JSON) или превышен его размер |
| `401 unauthorized` | токен отсутствует или недействителен |
| `404 not_found` | продукт не принадлежит профилю или не существует |
| `422 validation_failed` | некорректные поля: категория, несуществующая или неверно записанная дата, порядок дат, значения настроек |
| `409 conflict` | идентификатор продукта занят другим профилем |
| `500 internal_error` | внутренняя ошибка |

Формат тела ошибки:

```json
{ "error": "validation_failed", "details": ["category должен быть food или medicine"] }
```

`details` присутствует у `422`.

## Поведение и ограничения

- **Изоляция**: сервис работает в транзакции с `app.user_id`, поэтому RLS в PostgreSQL отдаёт только строки профиля запроса; обращение к чужому идентификатору даёт `404`.
- **Таймаут запроса**: `statement_timeout` — 10 секунд; более долгий запрос прерывается, соединение возвращается в пул.
- **Даты**: календарные, без времени и часового пояса.
- Сервис разворачивается на `192.168.3.69` (приватный адрес — вне домашней сети недоступен).
- Офлайн-режим, push-уведомления и TLS в объём не входят.
