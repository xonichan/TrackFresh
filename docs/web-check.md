# Проверка веб-версии в браузере

Инструкция для задач 1.3, 2.4, 5.1–5.5 изменения `add-web-app`. Проверяем собранную веб-версию,
которую раздаёт API, — не dev-сервер Metro.

## 0. Что понадобится

- **Проект Firebase** с включённым входом по почте и паролю и ключом сервисного аккаунта.
  Без него проверить нечего: API принимает только настоящий ID-токен, режима «отключить проверку»
  в нём нет.
- Браузер на этой машине (и, по желанию, телефон в домашней сети).
- Пароль к базе — в хранилище, команда ниже. Само значение печатать не нужно.

## 1. Настроить Firebase

В [консоли Firebase](https://console.firebase.google.com):

1. **Authentication → Sign-in method** → включить **Email/Password**.
2. **Authentication → Settings → Authorized domains** → добавить `localhost` и `192.168.3.69`.
   Без этого вход даст `auth/unauthorized-domain`.
3. **Project settings → General → Your apps** → добавить **веб-приложение** → скопировать
   `apiKey`, `authDomain`, `projectId`, `appId`.
4. **Project settings → Service accounts → Generate new private key** → сохранить JSON **вне
   репозитория**, например `C:\Users\onich\secrets\trackfresh-sa.json`.
   Это секрет: в git он не должен попасть (в `.gitignore` уже добавлены `service-account*.json`
   и `*firebase-adminsdk*.json`).

## 2. Вписать ключи веб-приложения

`mobile/app.json` → `expo.extra.firebaseWeb`:

```json
"firebaseWeb": {
  "apiKey": "AIza...",
  "authDomain": "your-project.firebaseapp.com",
  "projectId": "your-project",
  "appId": "1:1234567890:web:abcdef"
}
```

Это публичные ключи веб-приложения, они не секрет. **Ключи вшиваются в сборку при сборке**,
поэтому после правки `app.json` шаг 3 обязателен.

## 3. Собрать интерфейс

```bash
cd C:\Users\onich\sandbox\TrackFresh\mobile
npm run build:web
```

Файлы появятся в `api/public` — оттуда их раздаёт API.

## 4. Запустить API

В PowerShell (пароль читается из хранилища, ключи — из JSON, на экран ничего не выводится):

```powershell
$env:PGPASSWORD  = (& py -3 'C:\Users\onich\.secretvault\vault.py' get mini).Trim()
$env:PGHOST      = '192.168.3.69'
$env:PGDATABASE  = 'mydb'
$env:PGUSER      = 'trackfresh'

$sa = Get-Content 'C:\Users\onich\secrets\trackfresh-sa.json' -Raw | ConvertFrom-Json
$env:FIREBASE_PROJECT_ID     = $sa.project_id
$env:FIREBASE_CLIENT_EMAIL   = $sa.client_email
$env:FIREBASE_PRIVATE_KEY    = $sa.private_key

cd C:\Users\onich\sandbox\TrackFresh\api
npm.cmd run build
npm.cmd start
```

`npm.cmd`, а не `npm`: в PowerShell политика выполнения блокирует `npm.ps1`.

Каталог `api/public` при необходимости задаётся явно: `$env:WEB_DIR = 'C:\путь\к\api\public'`.
Другой порт: `$env:PORT = '3001'`.

## 5. Открыть

- на этой машине — `http://localhost:3000`
- с телефона в домашней сети — `http://192.168.3.69:3000`

Быстрая проверка, что сервер жив: `http://localhost:3000/health` → `{"status":"ok"}`,
корень адреса → страница TrackFresh (не JSON и не `Cannot GET /`).

## 6. Что проверять

### 1.3 — экраны открываются

1. Открыт экран входа: «TrackFresh», поля «Почта» и «Пароль», кнопки «Войти», «Создать аккаунт»,
   «Войти через Google».
2. Зарегистрироваться (переключиться на «Создать аккаунт», пароль не короче 6 символов).
3. Должны появиться три вкладки: «Список», «Добавить», «Настройки».
4. На вкладке «Добавить» **нет** кнопки сканирования и есть строка, что оно здесь недоступно.
5. На вкладке «Настройки» есть строка, что напоминания здесь не приходят.

### 2.4 — вход и выход

| Действие | Что ожидать |
|---|---|
| Пароль неверный | Сообщение «Неверная почта или пароль», данные не открываются |
| Пароль верный | Открывается список |
| «Выйти» внизу настроек | Экран входа; список пропадает |
| Обновить страницу (F5) после выхода | Снова экран входа, продуктов не видно |

### 5.1 — добавление

| Действие | Что ожидать |
|---|---|
| Пустое название, «Добавить» | «Укажите название.» |
| Срок годности `2026-02-30` | «Срок годности в формате ГГГГ-ММ-ДД.» (такой даты не существует) |
| Дата производства позже срока | «Дата производства позже срока годности.» |
| Название «Молоко», срок `2026-12-01` | Продукт появляется в списке |

### 5.2 — изменение и удаление

1. Открыть продукт из списка → «Изменить» → поменять название и срок → «Сохранить».
   В списке должно быть новое название.
2. Открыть продукт → «Удалить» → «Отмена»: продукт остаётся.
3. Повторить → «Удалить»: продукт исчезает из списка.

### 5.3 — список

1. Порядок: ближайший к истечению — первым.
2. Цвет проверяется через период предупреждения: в настройках поставить **30** дней, «Сохранить».
   - продукт со сроком через 20 дней — жёлтый;
   - срок вчера — красный;
   - срок через год — зелёный.
3. Фильтр «Продукты» / «Лекарства» / «Все» оставляет только выбранную категорию.

### 5.4 — настройки

1. Сменить частоту, время и период, «Сохранить» → «Настройки сохранены».
2. Обновить страницу (F5) → значения остались.
3. Время `25:00` → «Время в формате ЧЧ:ММ.»
4. Период `400` → «Период предупреждения — целое число от 0 до 365.»

### 5.5 — сервер недоступен и истёкший вход

1. Остановить API (Ctrl+C в его окне), обновить страницу.
   - Если список уже загружался, покажется баннер «Нет связи: N изменений ждут отправки» и
     список из кэша.
   - Чистый экран ошибки с кнопкой «Повторить» видно в **приватном окне** (там кэша нет).
   - Страница не должна зависать или падать.
2. Запустить API снова, нажать «Повторить» — список загружается, баннер исчезает.
3. Истёкший вход: в консоли Firebase удалить пользователя (или отключить). Затем в приложении
   нажать «Повторить» — должен показаться экран входа.

## 7. Что в браузере не работает намеренно

- **Сканирование упаковки**: нет ML Kit, поэтому кнопки нет и поля заполняются вручную.
- **Напоминания**: нет планировщика уведомлений, поэтому напоминания приходят только на телефоне.

Это ожидаемое поведение, а не дефект. Всё остальное — продукты, категории, сроки, фильтр, цвета,
настройки — работает и в браузере.

## 8. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| «Вход не настроен: в app.json не заполнен expo.extra.firebaseWeb» | Пустые ключи | Шаг 2, затем пересобрать (шаг 3) |
| `auth/unauthorized-domain` | Домен не разрешён | Добавить адрес в Authorized domains |
| Пустая белая страница | Сборка сделана до правки `app.json` | Пересобрать; открыть консоль браузера (F12) |
| Сразу выкидывает на экран входа | API не принимает токен: сервисный аккаунт из другого проекта | Сверить `projectId` в `app.json` и в JSON |
| `Ошибка конфигурации: не задана переменная окружения …` | Пропущена переменная | Шаг 4 |
| Порт 3000 занят | Другой процесс | `$env:PORT = '3001'` перед запуском |

## 9. Чего делать не стоит

Проверять через `npx expo start --web`: это отдельный origin (порт 8081), а CORS в API не настроен —
браузер заблокирует запросы к данным. Для проверки годится только сборка, которую раздаёт API.
