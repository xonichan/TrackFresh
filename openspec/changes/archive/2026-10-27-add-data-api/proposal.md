# Proposal

## Why

Приложение не может работать с PostgreSQL: точки доступа нет. Спеки `data-model` и `user-data-sync` требуют хранения данных в `products` и `user_settings` и изоляции доступа через RLS, но контракт «клиент → данные» не определён: неизвестно ни как приложение подключается, ни как в сессию попадает `app.user_id`.

## What Changes

- Появляется HTTP-API на Node.js + TypeScript (Express) — единственная точка доступа приложения к базе.
- Запросы аутентифицируются по Firebase ID-токену; профиль определяется по `firebase_uid`, при первом обращении профиль создаётся.
- Эндпоинты продуктов: создание, список, изменение, удаление.
- Эндпоинты настроек: чтение и обновление.
- Доступ к строкам ограничивается владельцем: API выставляет `app.user_id` при работе с базой.
- Срок годности и дата производства передаются как календарные даты (`YYYY-MM-DD`), без времени и часового пояса.

## Capabilities

### New Capabilities

- `data-api`: HTTP-контракт доступа приложения к данным пользователя — аутентификация запроса, операции над продуктами и настройками, модель ошибок, изоляция данных.

### Modified Capabilities

_Нет — требования `data-model` и `user-data-sync` не меняются; API их реализует._

## Impact

- Новый сервис: Node.js, TypeScript, зависимости (Express, `firebase-admin`, `pg`); конфигурация подключения к PostgreSQL и учётные данные Firebase Admin.
- Развёртывание на `192.168.3.69`. Адрес приватный — вне домашней сети API недоступен; мобильный доступ решается отдельно.
- Активное изменение `create-trackfresh-app` (0/24) описывает прямую работу клиента с Firestore; после появления API клиенту нужен он, а не Firestore — пересматривается отдельным изменением.
- Вне объёма: клиентская часть приложения, офлайн-синхронизация, доставка push-уведомлений, изменения схемы БД, TLS и внешний доступ.
