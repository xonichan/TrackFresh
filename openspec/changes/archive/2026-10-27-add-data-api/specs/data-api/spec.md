# Spec Delta

## Purpose

HTTP-контракт, через который мобильное приложение читает и изменяет данные пользователя в PostgreSQL: аутентификация запроса, операции над продуктами и настройками, модель ошибок и изоляция данных.

## ADDED Requirements

### Requirement: Аутентификация запроса
API SHALL принимать запрос только при наличии действительного Firebase ID-токена и отклонять остальные с ответом 401.

#### Scenario: Валидный токен
- **WHEN** запрос содержит действительный Firebase ID-токен
- **THEN** запрос обрабатывается

#### Scenario: Отсутствующий или недействительный токен
- **WHEN** токен отсутствует, просрочен или подделан
- **THEN** API отвечает 401 и не выполняет операцию

### Requirement: Определение профиля запроса
API SHALL определять профиль пользователя по идентификатору Firebase из токена и создавать профиль при первом обращении.

#### Scenario: Профиль существует
- **WHEN** пользователь с известным идентификатором Firebase обращается к API
- **THEN** запрос обрабатывается в контексте его профиля

#### Scenario: Первое обращение
- **WHEN** аутентифицированный пользователь обращается впервые
- **THEN** API создаёт профиль с его идентификатором Firebase и продолжает обработку

### Requirement: Создание продукта
API SHALL принимать данные продукта и сохранять его для профиля запроса.

#### Scenario: Корректный продукт
- **WHEN** приходит название, категория и срок годности
- **THEN** продукт сохраняется и возвращается с присвоенным идентификатором

#### Scenario: Некорректные данные
- **WHEN** категория недопустима или дата производства позже срока годности
- **THEN** API отвечает 422 и не сохраняет продукт

#### Scenario: Несуществующая календарная дата
- **WHEN** срок годности или дата производства не является существующей датой (например, `2026-02-30`)
- **THEN** API отвечает 422 и не сохраняет продукт

### Requirement: Список продуктов
API SHALL возвращать продукты профиля запроса, упорядоченные по сроку годности.

#### Scenario: Сортировка по сроку
- **WHEN** запрашивается список продуктов
- **THEN** ближайшие к истечению возвращаются первыми

### Requirement: Изменение и удаление продукта
API SHALL изменять и удалять продукт по его идентификатору в пределах профиля запроса.

#### Scenario: Изменение своего продукта
- **WHEN** приходит корректный набор полей для существующего продукта профиля
- **THEN** данные продукта обновляются

#### Scenario: Чужой или несуществующий продукт
- **WHEN** идентификатор не принадлежит профилю запроса
- **THEN** API отвечает 404 и не изменяет данные

### Requirement: Чтение и обновление настроек
API SHALL возвращать и обновлять настройки уведомлений профиля запроса.

#### Scenario: Чтение настроек
- **WHEN** запрашиваются настройки
- **THEN** возвращаются частота, время отправки и период предупреждения

#### Scenario: Обновление настроек
- **WHEN** приходит корректный набор значений
- **THEN** настройки сохраняются и возвращаются в обновлённом виде

### Requirement: Календарный формат дат
API SHALL передавать срок годности и дату производства как календарные даты в формате `YYYY-MM-DD`, без времени и часового пояса.

#### Scenario: Дата без сдвига
- **WHEN** продукт со сроком годности сохраняется и затем читается через API
- **THEN** возвращённая дата совпадает с переданной

### Requirement: Изоляция данных запроса
API SHALL предоставлять доступ только к строкам профиля запроса.

#### Scenario: Чужие данные недоступны
- **WHEN** профиль запроса обращается к данным другого профиля
- **THEN** операция отклоняется, чужие строки не возвращаются
