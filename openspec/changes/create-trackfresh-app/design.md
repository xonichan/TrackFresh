# Design

## Context

Зелёный проект — мобильное Android-приложение для отслеживания сроков годности. См. proposal.md для мотивации. Технологический стек определён заказчиком: React Native, Firebase, ML Kit.

## Goals / Non-Goals

**Goals:**
- Минималистичная архитектура React Native с навигацией через React Navigation
- Единый источник данных в Firebase Firestore с офлайн-поддержкой
- OCR-распознавание через ML Kit для сканирования упаковки
- Надёжная доставка push-уведомлений через FCM

**Non-Goals:**
- iOS-поддержка (только Android на данном этапе)
- Многопользовательский/семейный доступ
- Интеграция с внешними базами продуктов (штрих-коды)
- Web-версия приложения

## Decisions

### 1. React Native с Expo
**Выбор**: Expo (managed workflow) вместо bare React Native.
**Рationale**: Ускоряет разработку и сборку; Expo поддерживает Firebase и камеру из коробки. Если потребуется нативный ML Kit, переход на dev-client.
**Альтернатива**: Bare React Native — больше контроля, но дольше настройка.

### 2. Firebase Firestore как основное хранилище
**Выбор**: Firestore с включённым persistence (офлайн-режим).
**Rationale**: Firestore автоматически обеспечивает офлайн-доступ и синхронизацию, что закрывает требование офлайн-работы без дополнительного кода.
**Структура данных**:
- `users/{userId}` — профиль пользователя
- `users/{userId}/products/{productId}` — продукты (подколлекция)
- `users/{userId}/settings` — настройки (один документ)

### 3. ML Kit для OCR
**Выбор**: @react-native-ml-kit/text-recognition.
**Rationale**: Нативная Google-библиотека, работает без сети, хорошо распознаёт даты на упаковке.
**Альтернатива**: Tesseract.js — хуже качество, требует сети для WASM.

### 4. Навигация: React Navigation (Bottom Tabs + Stack)
**Выбор**: Bottom Tab Navigator для главных экранов (Список, Добавить, Настройки) + Stack Navigator для детальных экранов.
**Rationale**: Стандартный паттерн мобильной навигации, хорошо поддерживается.

### 5. Уведомления: Firebase Cloud Messaging
**Выбор**: @react-native-firebase/messaging с фоновым обработчиком.
**Rationale**: FCM — стандарт для Android push-уведомлений; интеграция с Firebase уже заложена.
**Подход**: Локальные уведомления для отображения + FCM для удалённого триггера из Cloud Functions (проверка сроков по расписанию).

### 6. Стейт-менеджмент: Context API + useReducer
**Выбор**: Встроенный React Context вместо Redux/Zustand.
**Rationale**: Для текущего масштаба приложения (3 экрана, одна сущность) Context достаточен. Если сложность вырастет — миграция на Zustand.

## Risks / Trade-offs

- **[OCR-качество]** → ML Kit может не распознавать нестандартные форматы дат. Митигация: всегда показывать предзаполненную форму для ручной корректировки.
- **[Expo-ограничения]** → Managed workflow Expo ограничивает нативные модули. Митигация: при необходимости перейти на Expo dev-client или bare workflow.
- **[Firestore-лимиты]** → Бесплатный тариф Firestore: 50K чтений/день. Митигация: кэширование на клиенте через persistence, минимальные запросы.
- **[FCM-доставка]** → Push-уведомления не гарантированы. Митигация: использовать локальные уведомления как резерв + Cloud Functions для надёжного триггера.
