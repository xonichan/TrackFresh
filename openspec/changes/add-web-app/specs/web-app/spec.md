# Spec Delta

## Purpose

Работа с продуктами и настройками из браузера: вход, список с фильтром и цветовой индикацией срока, добавление, правка и удаление продуктов. Возможности, которых в браузере нет (сканирование упаковки, напоминания), не показываются вовсе.

## ADDED Requirements

### Requirement: Вход в браузере
Веб-версия SHALL требовать входа в учётную запись и не показывать данные до него.

#### Scenario: Вход по почте и паролю
- **WHEN** пользователь вводит корректные почту и пароль
- **THEN** открывается список его продуктов

#### Scenario: Неверные данные для входа
- **WHEN** почта или пароль неверны
- **THEN** показывается сообщение об ошибке, данные не открываются

#### Scenario: Выход
- **WHEN** пользователь выходит из учётной записи
- **THEN** показывается экран входа, а данные предыдущего пользователя скрываются

### Requirement: Список продуктов в браузере
Веб-версия SHALL показывать список продуктов профиля, ближайшие к истечению первыми.

#### Scenario: Открытие списка
- **WHEN** пользователь открывает веб-версию после входа
- **THEN** отображаются его продукты, отсортированные по сроку годности

#### Scenario: Пустой список
- **WHEN** у профиля ещё нет продуктов
- **THEN** показывается пустой список и предложение добавить продукт

### Requirement: Цветовая индикация срока
Веб-версия SHALL помечать каждый продукт цветом статуса, а порог «истекает скоро» SHALL брать из настроек профиля.

#### Scenario: Порог из настроек
- **WHEN** период предупреждения в настройках равен N дней и до срока осталось не больше N
- **THEN** продукт помечается как истекающий скоро

#### Scenario: Просроченный продукт
- **WHEN** срок годности продукта уже прошёл
- **THEN** продукт помечается как просроченный независимо от периода предупреждения

### Requirement: Фильтрация списка по категории
Веб-версия SHALL позволять показать все продукты, только продукты или только лекарства.

#### Scenario: Выбор фильтра
- **WHEN** пользователь выбирает категорию
- **THEN** остаются только продукты выбранной категории

### Requirement: Добавление продукта в браузере
Веб-версия SHALL позволять добавить продукт, указав название, категорию и срок годности.

#### Scenario: Успешное добавление
- **WHEN** пользователь заполняет обязательные поля и сохраняет
- **THEN** продукт появляется в списке с указанными данными

#### Scenario: Незаполненные обязательные поля
- **WHEN** название или срок годности не заполнены
- **THEN** показывается ошибка, продукт не сохраняется

#### Scenario: Некорректная дата
- **WHEN** введена несуществующая дата, например 2026-02-30
- **THEN** показывается ошибка, продукт не сохраняется

### Requirement: Изменение продукта в браузере
Веб-версия SHALL позволять изменить поля ранее добавленного продукта.

#### Scenario: Успешное изменение
- **WHEN** пользователь изменяет поля продукта и сохраняет
- **THEN** обновлённые данные видны в списке

#### Scenario: Чужой продукт
- **WHEN** пользователь открывает продукт, которого нет в его списке
- **THEN** показывается сообщение, что продукт не найден, данные не изменяются

### Requirement: Удаление продукта в браузере
Веб-версия SHALL позволять удалить продукт после подтверждения.

#### Scenario: Удаление с подтверждением
- **WHEN** пользователь подтверждает удаление
- **THEN** продукт исчезает из списка

#### Scenario: Отмена удаления
- **WHEN** пользователь отменяет подтверждение
- **THEN** продукт остаётся в списке

### Requirement: Настройки уведомлений в браузере
Веб-версия SHALL показывать и сохранять частоту, время отправки и период предупреждения профиля.

#### Scenario: Изменение настроек
- **WHEN** пользователь меняет значения и сохраняет
- **THEN** значения сохраняются и остаются такими же после перезагрузки страницы

#### Scenario: Некорректные значения
- **WHEN** время не в формате ЧЧ:ММ или период предупреждения вне диапазона 0–365
- **THEN** показывается ошибка, настройки не сохраняются

### Requirement: Недоступные в браузере операции скрыты
Веб-версия SHALL не показывать операции, которые в браузере не работают: сканирование упаковки и напоминания на устройстве.

#### Scenario: Форма добавления без сканирования
- **WHEN** пользователь открывает добавление продукта в браузере
- **THEN** кнопки сканирования упаковки нет, поля заполняются вручную

### Requirement: Понятная ошибка при недоступном сервере
Веб-версия SHALL сообщать о недоступности сервера и позволять повторить запрос.

#### Scenario: Сервер недоступен
- **WHEN** запрос к серверу не проходит
- **THEN** показывается сообщение о недоступности и кнопка повтора, страница не зависает

#### Scenario: Истёк вход
- **WHEN** сервер отвечает, что токен недействителен
- **THEN** показывается экран входа
