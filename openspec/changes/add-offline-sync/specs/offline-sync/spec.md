# Spec Delta

## Purpose

Работа приложения без сети: локальный кэш данных, очередь изменений, отправка при появлении связи и разрешение конфликтов по времени изменения.

## ADDED Requirements

### Requirement: Локальный кэш данных
Система SHALL показывать ранее загруженные продукты и настройки без обращения к сети.

#### Scenario: Открытие без сети после успешной загрузки
- **WHEN** приложение открывается без сети, а данные уже загружались ранее
- **THEN** отображается сохранённый список продуктов и настройки

#### Scenario: Первый запуск без сети
- **WHEN** приложение открывается без сети и локальных данных ещё нет
- **THEN** показывается пустой список и сообщение об отсутствии связи

### Requirement: Изменения без сети
Система SHALL применять добавление, изменение и удаление продуктов локально, не дожидаясь сети.

#### Scenario: Добавление без сети
- **WHEN** пользователь добавляет продукт без сети
- **THEN** продукт сразу появляется в списке и помечается как неотправленный

#### Scenario: Изменение и удаление без сети
- **WHEN** пользователь меняет или удаляет продукт без сети
- **THEN** изменение сразу видно в списке, а прежнее состояние на сервере не затрагивается

### Requirement: Очередь отправки
Система SHALL отправлять накопленные изменения на сервер по порядку, когда связь появляется.

#### Scenario: Появление связи
- **WHEN** сеть становится доступной и в очереди есть изменения
- **THEN** изменения уходят на сервер по одному, а локальные данные выравниваются с серверными

#### Scenario: Сервер отклонил изменение
- **WHEN** сервер отвечает на изменение ошибкой проверки (422)
- **THEN** изменение снимается с очереди, а пользователь видит причину

### Requirement: Повторная отправка не создаёт дубликат
Система SHALL отправлять при создании продукта собственный идентификатор, чтобы повтор после обрыва связи не создавал второй продукт.

#### Scenario: Повтор после обрыва
- **WHEN** запрос на создание был отправлен, но ответ не дошёл, и система повторяет его
- **THEN** на сервере остаётся один продукт

### Requirement: Разрешение конфликтов по времени
Система SHALL разрешать расхождение между локальным изменением и серверной версией в пользу более позднего по времени изменения.

#### Scenario: Серверная версия новее
- **WHEN** серверная версия продукта изменена позже локального изменения
- **THEN** локальное изменение отбрасывается, в списке показывается серверная версия

#### Scenario: Локальное изменение новее
- **WHEN** локальное изменение сделано позже серверной версии
- **THEN** изменение отправляется и перезаписывает серверную версию

### Requirement: Удаление уже удалённого
Система SHALL считать удаление успешным, если продукт на сервере уже отсутствует.

#### Scenario: Повторное удаление
- **WHEN** отправляется удаление продукта, которого на сервере уже нет
- **THEN** изменение снимается с очереди как выполненное

### Requirement: Индикация неотправленных изменений
Система SHALL показывать, что есть изменения, ещё не дошедшие до сервера.

#### Scenario: Есть очередь
- **WHEN** в очереди остаются неотправленные изменения
- **THEN** пользователь видит признак «офлайн» и количество неотправленных изменений
